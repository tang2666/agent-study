# 09 — 框架对照（手写之后才看）

> **这个目录刻意排在很后面。**
> 现在你已经手写过循环、记忆、RAG、多 Agent 了。所以这一层不再是"学会用框架"，而是回答一个问题：
> **这个框架到底替我做了什么？值不值？**

## 要搞懂什么

- **框架抽象的是什么**：把你 `03` 写的 `while` 循环，换成了"状态图"。循环的每条边变成显式的转移
- **它额外给了什么**（这些是你手写版本没有的）：
  - **状态持久化 / 检查点**：跑到一半崩了能恢复
  - **人类介入（HITL）**：在某个节点暂停，等人批准再继续
  - **时间旅行**：回到之前的某个状态重跑
  - **流式事件**：把中间过程实时推给前端
  - **可视化**：把流程图画出来
- **它的代价**：
  - 抽象泄漏：出问题时你得同时理解你的逻辑**和**框架
  - 调试变难：堆栈是框架的，不是你的
  - 版本绑定：框架升级可能破坏你的代码
- **"不要重新发明"的边界在哪**：什么该用框架，什么该自己写
- **几个不同层次的东西，别搞混**：
  - **Agent 框架**（LangGraph 这类）：管循环和状态
  - **SDK 自带的循环助手**：只是把 `while` 循环包一层，帮你管工具执行，没有状态持久化
  - **完整的 Agent 产品 / SDK**：内置了工具集和权限系统，是个开箱即用的 Agent，不是脚手架

  **这三个经常被混为一谈，选型时问清楚你要的是哪一个。**

## 要写的代码

```
09-frameworks/
├── reimpl_task/            # 把 03 的任务用框架重写一遍
├── compare.md              # 逐项对比
└── verdict.md              # 你自己的结论
```

**第一步：挑一个任务用框架重写**

用 `03` 里那个需要多轮工具调用的任务，用 LangGraph（或其他 Agent 框架）重写一遍。

验收：
- [ ] 功能等价：输入输出和手写版一致
- [ ] 统计代码行数：**框架版 vs 手写版**，各多少行？
- [ ] 统计依赖：框架引入了多少个包？（`pip list` 数一下）
- [ ] 打印每一步的执行日志，和手写版的日志对比

**第三步：那些你手写时很难做的事**

重点测这几项 —— 它们才是框架的真正价值：

验收：
- [ ] **中断恢复**：跑到第 5 步杀掉进程，重启后能从第 5 步继续吗？手写版能做到吗？要写多少代码？
- [ ] **人工介入**：设计一个"执行删除操作前必须人工确认"的流程。框架版怎么写？手写版呢？
- [ ] **时间旅行**：回到第 3 步，改一个参数，重新往后跑。框架支持吗？
- [ ] **可视化**：框架能把你的流程画出来吗？这东西对你有什么用？

**第四步：`verdict.md` — 写你自己的结论**

验收：
- [ ] 明确回答：**什么规模的项目该用框架？什么规模不该？**
- [ ] 举一个你**具体的**场景，说明你会选哪个，为什么
- [ ] 说出框架至少一个你在手写时**没想到**的好处
- [ ] 说出至少一个框架让你**难受**的地方

## 刻意不做的事

- **不比较"哪个框架最好"**。这种比较没有意义，框架演化很快，你的能力和场景才是变量
- **不抄官方 README 的对比表**。所有结论必须是你跑出来的
- **不要因为框架"看起来更专业"就选它**。`03` 那个手写循环，在固定任务上可能比框架版更快、更便宜、更好调

## 踩坑提醒

- **框架的抽象是有方向的**：它让常见路径变简单，让不常见路径变难。你的需求如果偏门，会跟框架打架
- **框架版本变动频繁**，网上的教程很多已经过时。以你自己装的版本的文档为准
- **小心"样例跑通 = 会用"的错觉**。真正的考验是需求稍微偏离样例的时候
- 有些框架会把提示词也管起来，你调了半天没效果，最后发现是框架在中间插了东西

## 自测问题

1. 用一句话说清：框架替你做的**核心那一件事**是什么？
2. 你手写的 `03` 版本，加"崩溃恢复"要改多少？框架版呢？
3. 什么情况下你会**主动选择**不给项目上框架？
4. Agent 框架、SDK 的循环助手、完整 Agent 产品，三者的区别是什么？你现在的需求属于哪一类？
5. 如果框架明天停止维护了，你的项目会怎样？
